# Swarmie 0.1.2

**Pre-1.0 patch release.** This release focuses on in-game usability and the
robot's idle presence. It does not change the Adapter contract (`0.1`).

## Highlights

- New quick commands that do not require a selector:
  - `/swarmie list`
  - `/swarmie select <index|uuid>`
  - `/swarmie selected`
  - `/swarmie spawn`
  - `/swarmie remove`
- `/swarmie fly`, `stop`, `status` and `results` now accept a selected robot
  when the target argument is omitted. Selector-based multi-target forms remain.
- `remove` requires an explicit selection; it never auto-deletes the nearest
  robot.
- Hover presentation lowered to a 0.32-block visual offset, with a more visible
  ±0.055-block idle bob and stronger ear/side-fin motion.
- Existing `/swarmie help` now includes a `selection` topic.

## Verification

- 75 Java main tests, 12 contract tests.
- 66 Python SDK/mock tests.
- 33 audit tests; completeness validator `errors=0`, `review_findings=0`.
- Real client chat: `spawn`, `list`, `status`, short `fly`/`stop` and explicit
  `remove` executed successfully.
- Real client visual check: hover offset and idle animation.

## Known limitations

- DCPU/MMIO remains a test-only subset experiment.
- SDB v0 remains a draft specification; no device bus implementation.
- `LocalSensor` remains internal/debug, not a public sensor API.
- No general farming, pathfinding, task scheduling, orientation setpoint or
  public region/entity/sensor observation.
- Dedicated-server startup and second-client synchronization remain unverified.
